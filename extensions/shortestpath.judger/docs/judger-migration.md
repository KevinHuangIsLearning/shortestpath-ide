# ShortestPath Judger 迁移与新功能

本插件保留 CPH Plus 的 GPL-3.0-or-later 许可证和原作者署名；新增功能依据用户提供的 CPH-NG 0.7.11 行为规范独立实现，没有引入该项目源码。独立捆绑的 testlib 来自其官方仓库，许可证为 MIT，固定版本与许可证位于 `static/testlib/`。

## 配置与数据

- 扩展 ID：`shortestpath.judger`。配置前缀：`judger.*`。
- 每次激活时检查全局、工作区、文件夹及合法语言覆盖中的显式旧配置。已有新配置优先；新值写入成功后删除对应旧键，已有新值时直接清理旧键。写入或清理失败会保留未处理的旧项供下次重试，此前仅复制配置的版本也会自动完成清理。成功清理后恢复默认不会重新导入旧值；无法迁移的未知键或不支持的作用域保留，避免丢失配置。
- 旧 `cph.*` 命令作为兼容别名保留；原快捷键不需立即重设。
- 首次读取旧题目时，将旧版 `.cph` 下的 `.prob` 自动迁入工作区 `.shortestpath` 下的 `.prob.judger/`，无需再编辑保存；原数据保留作备份。自定义保存位置继续尊重原设置。新格式存储版本化元数据和独立 `.in/.out`，超过 64 KiB 的旧内联内容改为文件引用。明确删除题目测试点时会同时删除当前数据和旧备份，防止旧数据重新出现；源码不删除。
- Companion 默认继续使用 27121。外部 CPH/CPH-NG 同时监听该端口会冲突。

## 导入测试点

评测面板的“导入测试点”入口选择 ZIP 或拖放 ZIP 都会递归查找测试数据，同目录同名配对，默认 `.in` 与 `.ans`／`.out`（按此优先级）匹配。有输入无答案、只有答案的条目也保留。自然序排序、多选默认全选，导入追加到当前题目；用户切换题目时不会把返回的数据插入另一题。

ZIP、文件和文件夹导入均保存输入与答案的文件路径，面板显示打开文件按钮，不将整个文件加载进文本框。保存和重载保留引用；评测时才由扩展宿主读取数据。文件样例输出上限为 16 MiB，面板最多收到 64 KiB 预览，完整输出通过文件打开。

“从文件导入测试点”支持单文件配对，`judger.problem.foundMatchTestcaseBehavior` 为 `always`、`ask` 或 `never`。扩展名通过 `inputFileExtensionList` 和 `outputFileExtensionList` 配置。

`judger.problem.unzipFolder` 默认 `${problem}/testcases/${zipBasenameNoExt}`，`${problem}` 为当前题目的 `.prob.judger/` 数据目录，另支持 `${workspace}`、`${zipDirname}`、`${zipBasename}`。导入时按原 ZIP 的 SHA-256 复用已解压目录，不检查展开文件内容；ZIP 内容改变时使用数字后缀保留旧数据。重复拖拽同一 ZIP 不增加重复的文件样例。ZIP 压缩前后各限 128 MiB、最多 10000 项；拒绝越界路径、符号链接和重名项。默认保留原压缩包；开启 `deleteAfterUnzip` 后，仅在解压、选择测试点后删除，取消选择不会删除原 ZIP。

“从文件夹导入测试点”与 ZIP 共用递归扫描、配对、多选和追加流程。旧 Large TC 独立入口、协议与执行逻辑已移除，大样例通过此入口导入为普通文件型测试点。按住 Shift 可向评测面板拖入 ZIP、测试数据文件和文件夹，这是 VS Code 的 Webview 拖放规则。“导入测试点”入口位于“更多操作”外，点击后弹出 ZIP、文件、文件夹、JSON 四种导入方式；选择 JSON 打开原有 JSON 导入界面，Shift 提示保持可见。底部加号用于添加空白样例。系统拖放无法提供文件路径时，通过浏览器读取文件内容暂存导入，仍被测试点引用的文件会保留，未被引用的暂存目录完成后清理；最多 128 MiB、10000 项。

## Checker、交互与运行工具

- 原 Python checker 继续接收“输入文件、选手输出文件”两个参数。
- testlib C++ checker 会自动编译，或直接运行已编译程序，接收“输入文件、选手输出文件、标准答案文件”三个参数；stderr 与退出码保留。testlib 头文件已内置，不需要从 CPH-NG 获取。
- Checker 状态包括 AC、WA、PE、FAIL、PARTIAL、TLE（checker 超时）、RE（checker 启动失败、崩溃或异常退出）、CE（C++ checker 编译失败）。面板单独显示 Checker 状态，保留日志与退出码，不混入选手程序的退出状态。Python checker 保留退出码 0 为 AC、1 为 WA 的旧约定，其他异常退出为 RE；Python 语法错误属于 RE。
- 在评测面板 checker 区填写交互程序路径，可选 C++ 源码或可执行文件。其参数为“输入文件、交互反馈文件”，标准输入输出与选手程序双向连接，共同受超时和停止操作控制。交互题不启用程序内计时包装。
- `judger.execution.mode` 默认为 `native`；`native` 对原生可执行程序记录 CPU 时间和峰值内存，其他语言使用普通执行；`instrumented` 为 C++ 加入程序内计时，报告缺失时保留原进程计时。原生工具首次使用时以用户 C++ 编译器编译。
- `redirectStdio` 默认关闭；开启时忽略 C++ 的 `freopen(..., stdin/stdout)`，使常见 OI 文件读写代码使用测试点流。这不是任意文件访问重定向，也不是沙箱。
- 统一比较区分 AC／PE／WA；行尾空格、Tab、CR 和末尾空行忽略，其他纯空白差异是 PE。`acceptPresentationError` 决定 PE 是否通过。已移除旧比较器和 comparison 设置；文件型样例使用同一判题流程。

## 提交用户脚本

内置 Codeforces、AtCoder、Hydro、VJudge、洛谷五类脚本。它们依据 0.7.11 的静态页面接口编写；网站页面可能变化，需要在实际账户中验证。登录、验证码和浏览器挑战由用户完成。

`judger.submission.autoSubmit` 默认关闭：填表后用户检查并点击最终提交；开启后脚本点击最终提交。完成点击不等于网站接收成功或判题通过。`languages` 可按主机名设置网站语言选项值，未配置时保留网站选择，不会猜语言 ID。

通过命令 **Judger：安装提交用户脚本** 安装 `.user.js`，或在 `judger.submission.userScripts` 配置本地路径。脚本按实际提交 URL 的 `@match`／`@include`／`@exclude` 匹配，支持 `@run-at`。`Judger` 对象提供 `code`、`url`、`language`、`fileName`、`autoSubmit` 等值。自定义脚本优先；已有 URL＋JS 配置仍保留并优先使用。

支持的 GM 子集：样式、键值存储、剪贴板、通知、资源文本／URL、文本／JSON 网络请求及相应 Promise 形式。`@require`、`@resource` 仅支持 HTTP(S)，单资源限 4 MiB。网络请求须声明 `@grant`，跨源还须声明 `@connect`，不共享浏览器登录 Cookie，不跟随重定向，响应限 8 MiB。特权脚本运行于独立 JS 上下文；`unsafeWindow` 仅用于无特权脚本，不能与 GM 特权组合。并非完整 Tampermonkey 实现，不支持 Chrome 扩展 API、Web Store、service worker 或通用浏览器网络规则。

脚本仅在 Judger 发起提交时运行，不会自动注入用户的全部浏览器标签页。


## 2026-09-27 IDE 功能补充

样例卡片的更多菜单提供启用/禁用、移动、文件/文本转换、原生 diff 和设为答案；卡片停止只取消当前普通样例，顶部停止结束整个运行。题目菜单支持详细配置、原始 JSON、复制及最近题目切换。

新增编译策略 auto/force/reuse、编译超时、展开及状态过滤、生成器与标程独立时限。默认编译产物位于 `.shortestpath/bin/`。无法可靠追踪依赖时 auto 保守重编译。大样例保持文件引用；完整输出落盘而只给 Webview 有界预览。

Companion 继续由扩展直接接收，没有独立接收器或路由进程。最近题目及结果缓存不等于多题并行调度，后者尚未实现。完整差异和验证见仓库 `reports/judger-cph-ng-parity-2026-09-27.md`。

## 题目文件、计时与对拍

导入 ZIP 和浏览器拖放暂存文件保存在当前题目的数据目录中。旧题目管理的大文本文件迁入该目录，旧副本保留；用户手选的外部文件仍保留原引用。ShortestPath OJ 的题面、题解、提交历史和题面版本同样保存在对应题目目录，尚未绑定源码的题目有独立目录。`.shortestpath/oj-index.json` 仅记录位置，不存题面正文；旧平铺 JSON 和先前绑定位置保留作迁移备份，读取时由索引选择当前位置，避免多窗口迁移误删数据。

题目用时记录开始时间戳，界面用当前时间相减，每秒刷新不会保存数据。“标记 AC”记录结束时间戳并停止计时，重载保持停止。旧累计用时在首次读取时迁移；复制题目会重新开始计时。

对拍参照 CPH-NG 0.7.11 的生成器 → 暴力解 → 普通判题流程，目标程序使用题目编译参数、比较模式、checker／interactor、时间与内存限制。0 次表示持续对拍直到停止或发现差异；发现差异时自动保存反例，大文本保留为题目目录内的文件引用。生成器和暴力解各自使用独立时限。

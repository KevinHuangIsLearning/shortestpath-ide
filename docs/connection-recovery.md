# 题目连接恢复

IDE 选中缓存题目或当前网页连接断开时，使用内置浏览器会话，隐藏加载同站点的 `/ide/connect?token=…`。浏览模式的网页与后台连接明确使用同一个应用级持久会话，不随代码工作区改变；OJ 扩展仍要求可信工作区。后台页面不占编辑器标签，不唤醒或聚焦应用。用户的外部浏览器登录不与内置浏览器共享。

恢复 token 由当前 IDE 实例生成，绑定站点、账号和完整 SolveTarget。切题、关闭题目、重新生成 token 后，旧请求失效。网页通过 `bridge.recovery.context` 获取目标，通过 `bridge.recovery.status` 通知登录或网络状态。`problem.resume` 校验目标后只刷新缓存与题目状态，不调用题目导入或 CPH 样例导入。

登录失效、账号不匹配或网站正在进行人机验证时暂停整页重试，并自动切换到浏览模式显示已加载的页面，无需点击题目详情中的按钮。重复状态通知不会反复抢焦点，按钮仍可用于手动返回验证页面；登录或验证完成后复用该页面的连接并返回做题模式，避免再次读取题面或触发验证。显示出的页面不受后台连接超时重载影响。加载中的登录或验证请求也会在页面准备好后显示；若准备好前已恢复连接，则取消待执行的跳转。恢复成功后隐藏连接提示。

## 浏览与做题

缓存题目的题面在恢复连接前即可显示，切题和断线不会用登录或验证按钮替换整个内容区。普通后台重连只更新状态；确认需要登录、账号切换或验证时显示小条提示，并保留自动跳转。连接状态独立于提示是否显示同步到 Webview，断线期间提交、提示解锁和评价等联网操作仍按原有规则禁用；本地题面、样例和已缓存内容可继续查看。

题目缓存保存到 IDE 为扩展提供的内部存储目录，优先使用工作区 `storageUri`，无工作区存储时使用 `globalStorageUri`；其下按代码文件夹 URI 的 SHA-256 分隔，目录结构为 `problem-cache/<hash>/`。不再向代码目录创建 `.shortestpath`。首次读取自动迁移旧目录中的有效记录、源码关联与最小连接身份，新位置写入并逐文件校验成功后才删除旧缓存记录；旧目录清空后删除。已有内部缓存优先，旧目录中无关或无法识别的文件保留，源码和 CPH 用例不迁移。

每个工作区的题目缓存最多保留 30 道题目的持久化快照，按 LRU 淘汰。打开、选中、导入和恢复题目更新记录中的 `lastUsedAt`，后台状态或评测结果写入不更新使用顺序；重启继续使用磁盘上的顺序。旧记录首次升级以文件修改时间初始化使用时间。超限时先保存保留项，再删除最久未使用的题目快照及其缓存题解、提交历史和旧题面。源码路径及最小连接身份（站点、账号、题目目标）保存在独立的 `.source-paths.json` 索引中；被淘汰的题目再次打开时自动联网恢复，不重新导入样例。淘汰不删除源码或 CPH 用例，也不改变一小时租约规则。读取及更新串行执行，只写变化的文件，失败写入等待同批文件全部结束后才放行后续操作。

顶部固定的「浏览 / 做题」切换与 `Ctrl/Cmd+Shift+Space` 切换同一窗口内的两个界面。浏览界面有自己的标签、导航和地址栏；做题界面的编辑器、CPH、题目面板独立保留。切换模式保留网页滚动与输入、未保存代码和光标，不重新加载页面。应用重启恢复模式、网页地址与选中的标签；网页本身重新加载。登录回调与连接 token 不写入普通标签恢复数据。

首次环境配置完成后进入浏览模式。网站「开始做题」激活做题模式并聚焦代码；「继续做题」使用 `problem.activate`，不重新导入样例。未打开代码文件夹时先选择一次保存文件夹，窗口加载该文件夹后接续导入。已导入、题面未变且账号与目标相同的题目重复绑定也复用现有源码与 CPH 用例。题目面板「在网页中查看」返回浏览模式并复用相应网页标签。

浏览期间收到新的评测结果，只标记做题按钮，不抢焦点。网页退出登录通过同源 storage 事件同步到其他网页及后台连接；连接只在首次恢复和身份变更时验证会话，空闲时不定期请求会话接口。外部浏览器另行登录使 IDE 会话失效后，下一次业务请求通过 401 响应处理退出。后台不登录、不复制外部浏览器 Cookie、不改变网站单账号单会话规则。

开题或恢复时同步一次计时基准，IDE 面板本地走秒。网页使用开题时间计算快照，不再每 10 秒推送或因计时变化推送状态；提交结果、提示内容、点赞等实际状态变化仍同步到 IDE。隐藏连接页不运行逐秒计时循环。

隐藏连接页不在提示解锁时主动请求服务器。IDE 本地倒计时结束后启用「查看提示」，用户点击时通过只读 `hint.state.request` 获取提示状态和内容；网络失败或尚未解锁时不自动重试。查看答案仍使用原有显式操作。

网页 WebSocket 重试采用 1、2、4、8 秒退避，短暂断线不同时触发 IDE 整页重建；后台连接页加载及绑定有超时保护。网站通过 `verification_required` 通知验证码（含排队及组件恢复）的等待状态，结束后发送 `connecting` 恢复超时保护；已绑定连接收到该通知仍保持已连接。每次仅管理当前题目的一个页面，异步返回的旧页面立即关闭，扩展宿主退出时释放页面。

恢复后只读取提交历史、重新观察已有提交、读取既有诊断任务或操作回执。不会自动重发提交或创建收费任务。源码、CPH 自定义用例和题目面板布局保持原样。

## 验证

- `npm run typecheck-client`
- `npm test --prefix extensions/shortestpath.oj`
- `npm test --prefix extensions/shortestpath.setup`
- `./scripts/test.sh --glob '**/extHostBrowsers.test.js'`
- 修改文件的 ESLint 和 `git diff --check`

2026-10-03 的本地联调使用 Next 开发站、模拟只读 API 和真实桥接 WebSocket，验证恢复、断线重连、账号不匹配、登录失效跳转及过期 token；题目导入计数始终为零。独立 macOS 开发实例验证隐藏加载不增加编辑器标签、后台 WebSocket 执行、显式显示与关闭、持久 Cookie，以及 ShortestPath HTTPS 页面到本地 WebSocket 的连接。

双模式验证覆盖网站继续做题不重复绑定、同源退出立即关闭连接、登录恢复后返回做题、重复网页地址的标签恢复与源码复用边界。真实 macOS 普通应用窗口验证切换保留代码与光标、重载保留未保存代码和网页滚动/输入、不创建重复原生页、后台标签不抢焦点，以及浏览页与隐藏页共享同一模拟 Cookie。测试使用临时配置与本地模拟账号，不操作真实账号。扩展开发宿主本身不保存磁盘备份，因此未保存代码重载验证使用普通应用窗口。

网站必须部署匹配的 `/ide/connect` 页面，IDE 必须使用支持隐藏浏览器和恢复协议的构建。只有一端更新不能完成自动恢复。本次仅修改本地两个仓库，未部署生产网站。
